Mục tiêu:
Tạo một project backend hoàn chỉnh, sạch, dễ mở rộng, có đầy đủ các component thường dùng trong dự án thực tế: REST API, database, authentication, authorization, Swagger/OpenAPI, migration, logging, exception handling, validation, testing, Docker, cấu hình môi trường, và tài liệu hướng dẫn chạy project.

Các chức năng bắt buộc:
1. Authentication và Authorization
- API đăng ký tài khoản.
- API đăng nhập.
- Sinh access token bằng JWT.
- Có refresh token nếu thiết kế phù hợp.
- Mã hóa password bằng BCrypt.
- Phân quyền theo role: ADMIN, USER.
- Một số endpoint public và một số endpoint cần authentication.
- Ví dụ:
  - POST /api/v1/auth/register
  - POST /api/v1/auth/login
  - POST /api/v1/auth/refresh-token nếu có refresh token
  - GET /api/v1/users/me
  - GET /api/v1/admin/users chỉ ADMIN được truy cập

2. User management
- Entity User gồm tối thiểu:
  - id
  - username
  - email
  - password
  - fullName
  - enabled
  - createdAt
  - updatedAt
- Entity Role.
- Quan hệ User - Role phù hợp.
- CRUD user cơ bản cho ADMIN.
- API lấy thông tin người dùng hiện tại.

3. Database
- Dùng PostgreSQL.
- Có file docker-compose.yml để chạy PostgreSQL.
- Có Flyway migration ban đầu:
  - tạo bảng users
  - tạo bảng roles
  - tạo bảng user_roles
  - insert role mặc định ADMIN, USER
  - có thể tạo user admin mặc định nếu phù hợp
- Không hard-code thông tin database trong code, dùng biến môi trường hoặc application.yml.

4. API response chuẩn hóa
Tạo cấu trúc response thống nhất, ví dụ:
{
  "success": true,
  "message": "OK",
  "data": {},
  "errors": null,
  "timestamp": "..."
}

Với lỗi:
{
  "success": false,
  "message": "Validation failed",
  "data": null,
  "errors": [
    {
      "field": "email",
      "message": "Email is invalid"
    }
  ],
  "timestamp": "..."
}

5. Exception handling
- GlobalExceptionHandler dùng @RestControllerAdvice.
- Xử lý các lỗi:
  - validation error
  - unauthorized
  - forbidden
  - not found
  - duplicate resource
  - business exception
  - internal server error
- Không expose stack trace ra client.

6. Validation
- Dùng Jakarta Bean Validation.
- Validate request DTO:
  - email đúng định dạng
  - password tối thiểu 8 ký tự
  - username không rỗng
  - các field bắt buộc

7. Swagger/OpenAPI
- Tích hợp springdoc-openapi.
- Swagger UI chạy được.
- Cấu hình title, description, version.
- Có Bearer JWT security scheme để test API bảo mật trực tiếp trên Swagger.
- Tất cả controller có mô tả API rõ ràng bằng annotation OpenAPI nếu cần.

8. Logging
- Có logging chuẩn bằng SLF4J.
- Log request quan trọng, lỗi hệ thống.
- Không log password/token nhạy cảm.
- Có thể thêm request correlation id nếu phù hợp.

9. Audit fields
- Entity base có:
  - createdAt
  - updatedAt
  - createdBy nếu phù hợp
  - updatedBy nếu phù hợp
- Dùng JPA Auditing.

10. Pagination và filtering
- API list user hỗ trợ pagination:
  - page
  - size
  - sort
  - keyword nếu phù hợp
- Response trả metadata:
  - page
  - size
  - totalElements
  - totalPages

11. Testing
- Viết unit test cho service auth/user.
- Viết integration test cho một số API chính nếu phù hợp.
- Test đăng ký, đăng nhập, truy cập endpoint cần JWT.
- Dùng test profile riêng.

12. Docker
- docker-compose.yml gồm:
  - PostgreSQL
  - optional: pgAdmin nếu phù hợp
- Dockerfile cho Spring Boot app.
- Hướng dẫn chạy bằng Docker Compose.

13. Cấu hình môi trường
Tạo các file:
- application.yml

- application-test.yml
